- מעבר בין תפקידים הוא כלי הדגמה, ואינו מנגנון אימות או הרשאות לייצור.
- הריפו והפרויקט הציבורי נפרדים מ־family360 וממערכת הייצור. הריפו ואתר הדמו ציבוריים.

## אחסון קבוע ב־GitHub Pages

האתר נבנה מהקוד בענף main באמצעות .github/workflows/pages.yml. כל push ל־main מפעיל התקנת חבילות, בדיקות יחידה, בנייה ובדיקות דפדפן, ורק לאחר הצלחתן מפרסם את dist ל־GitHub Pages. אפשר להפעיל את אותו תהליך ידנית במסך Actions. פרסום גרסת מנטה ואוויר בדמו אושר על ידי בעל הפרויקט. תהליך זה מפרסם את ריפו הדמו בלבד ואינו משנה את מערכת הייצור.

כתובת הפיתוח המקומית לאחר preview: http://127.0.0.1:5248/family360-preview/

הגדרת Pages בריפו צריכה להיות GitHub Actions, ולא תיקיית docs. הגדרת base ב־Vite מתאימה לנתיב הריפו. אין צורך במפתחות שירות או בסודות לפריסה; הרשאת הפרסום זמינה רק לעבודת deploy.

GitHub Pages אינו משתמש בקובץ _headers של Cloudflare. מדיניות CSP ו־no-referrer מוטמעות ב־HTML, יחד עם בקשה לאי־אינדוקס. אין בכך בקרת גישה: כל אדם שמקבל את הקישור יכול לפתוח אותו. הגדרת האחסון אינה משנה סינון רשת של המבקרים.

## המשך פיתוח מקומי — מסלול לקוח, 19.10.2026

מסך הפתיחה כולל כעת „התחלת דמו של לקוח חדש”. הפעולה מאפסת את נתוני ההדגמה ומציגה מסלול שאלון → מסמכים → המשך עם הנציג. שלב התשלום מוצג בנפרד כלא פעיל, ללא מחיר, חיוב או סימון שולם. אחרי שליחת השאלון נוצרת בקשת דוח לדוגמה בלבד, ולא רשימת דרישות אישית שנבדקה מקצועית.

הלקוח יכול לצרף דוגמה מובנית ללא בחירת קובץ ולראות שהמסמך ממתין לבדיקה. הרשאות העלאה ואישור נשמרות בנפרד; סימולציית הצירוף מוגבלת לתיק הלקוח או לצוות. מסמך שנדחה מציג סיבה ומאפשר ניסיון נוסף. מדריך המסמכים מציג דוגמאות מתוך הגדרות הפרויקט, ומבהיר שהבקשות בתיק הן הרשימה הרלוונטית ללקוח.

בדיקת הרצף: `npm run test:client-intake` מול preview בפורט 5250 או DEMO_URL. אין חיבור לסליקה או העלאת קבצים אמיתית. השינויים האלה מקומיים וטרם פורסמו.
