# סיכום שיחה למשפחה

סיכום שיחה מבוסס על החלטות והערות שהנציג שמר. אין תלות בהקלטה או בתמלול. זהו מסמך נפרד מדוח סיום הטיפול, ואישורו אינו מסיים טיפול במשפחה.

## מבנה המסמך

- כותרת קבועה וממותגת, ירוק עמוק ונחושת על נייר לבן חם.
- שם המשפחה, מספר התיק ושם הנציג נמשכים מנתוני התיק. תאריך הסיכום הוא תאריך יצירת הטיוטה, לא תאריך משוער של שיחת טלפון.
- בכל נושא: הכותרת והחלטת המשפחה מגיעות מהתיעוד השמור; הנציג בוחר אם לכלול את הנושא ועורך פסקה למשפחה.
- צעדים הבאים כוללים רק משימות שהוגדרו גלויות ללקוח. פרטי חיוב ודוח כספי אינם נוצרים כאן.
- שם המאשר, מועד האישור וגרסת המסמך נשמרים בעת ההצגה למשפחה.

## מסלול העבודה

בסיכום סביבת השיחה, לרבות שיחות ישנות: הכנת סיכום מהשיחה → תצוגה מקדימה → עריכת הנושאים → בדיקת כל נושא שנבחר → שמירת הטיוטה → בדיקת המסמך המלא → אישור והצגה למשפחה. ניתן להדפיס או לשמור PDF מתוך המסמך בלבד.

הערות המקור נטענות תחילה לטיוטה פרטית, ולא לאזור המשפחה. הנציג צריך להסיר תיעוד פנימי ולאשר כל נושא. הערה ארוכה מ־3,000 תווים אינה נחתכת אוטומטית; יש לנסח עבורה פסקה קצרה. שינוי בשם המשפחה או בתיעוד המקור מחייב רענון ובדיקה. תיקון לגרסה שאושרה פותח טיוטה חדשה; המשפחה ממשיכה לראות את הגרסה האחרונה שאושרה.

## סיוע בניסוח

בנפרד מהתבנית הקבועה, אפשר לבקש נוסח קצר למשפחה להערה מסוימת. זהו אותו מנגנון AI קיים, אותו מפתח ואותו מודל; לא שירות חדש. הבקשה מוגבלת לנושא ולהערה, אינה מייצרת זהות, החלטות או משימות. הסיכום מותר גם לאחר סיום שיחה, בעוד שאר כלי השיחה נשארים מוגבלים לשיחה פעילה. הפלט נבדק מול מזהי מקורות, מספרים שהופיעו בהערה ואיסור על כותרת שם משפחה. ההצעה נכנסת לעריכה רק בלחיצה מפורשת, מאפסת את בדיקת הנושא, ואינה נשלחת למשפחה בעצמה. המסלול הידני עובד גם כשהשירות אינו מחובר. בדמו הפלט סינתטי ומסומן כהדגמה.

## שמירה והרשאות

מיגרציה `0010_conversation_summaries.sql` מוסיפה טיוטה אחת לכל שיחה והיסטוריית גרסאות מאושרות. כל שינוי נבדק מול גרסה ומקור עדכניים ונשמר בעסקה. נציג חייב הרשאה למשפחה; אישור דורש `analysis.approve`. לקוח מקבל רק snapshot מאושר של משפחתו, ללא הערות מקור וטיוטות. שיתוף פירושו הצגה באזור האישי והתראה פנימית. לא נשלח דוא״ל.

## אימות

`npm run test:conversation-summary` בודק בדפדפן מסלול נציג → עריכה ובדיקה → אישור → פתיחה כלקוח → תיקון טיוטה בלי שינוי הגרסה המאושרת, ב־1440, 390 ו־320 פיקסלים, כולל הדפסה מבודדת ובלי גלילה אופקית. בדיקות השרת בודקות זהות מדויקת, הפרדת תיעוד פנימי, הרשאות, שינויים במקור, גרסאות והתנגשויות. `npm run test:ai-summary:live` הוא בדיקת ספק מפורשת ומקומית עם נתונים מומצאים בלבד.

פרסום הדמו אינו מפעיל את שרת הייצור, אינו מחיל מיגרציות על מסד נתונים מרוחק ואינו מגדיר בו סודות.
