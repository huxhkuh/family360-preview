# ביקורת רצפים לפי תפקיד — 27.10.2026

המטרה: בכל צומת פעולה ברורה, מצב שמירה מובן והמשך נגיש. דף הבית והנוסח השיווקי נשמרו.

## מסלולים שנבדקו

- לקוח: הרשמה ותשלום מדומה, שאלון וטיוטה, הפסקה וחזרה, מסמך שנדרש, השלמת פעולה, תיקון סימון ובקשת עזרה, המתנה ודוח סופי.
- נציג: קליטת שאלון, סקירה לקריאה פרק־פרק ובחירת תחום, בקשת מסמך ובדיקתו, שיוך ניתוח, החזרה עם סיבה, אישור, תיאום פגישה חדשה, החלטה, שיוך ביצוע ואישור סיום.
- בעל מקצוע: משימה משויכת חדשה, מסמכים ששותפו בלבד, טיוטה והגשה, השלמה אחרי החזרה, תחילת ביצוע, עדכון, המתנה, דיווח סיום והמתנה לאישור.
- מנהל: תור אישורים, בדיקת מסמך וביצוע, פתיחת תיק, טיוטות ניהול ותיקון שגיאות, הפניות ועמלות; שיוך נציג נבדק גם מול כללי הרשאה ושמירה מקבילה.
- משווק: העתקת קישור, צפייה בהפניות ובעמלות המורשות, רישום מהקישור ושיוך הפניה; חסימת גישה לתיק משפחה.

## תיקונים

1. חוברו פעולות דמו שחסרו: שליחה לניתוח/ביצוע, אישור/החזרת ניתוח, יצירת פגישה עם ממצאים אמיתיים מהניתוח, פתיחת תיק ושיתוף/ביטול שיתוף מסמך.
2. שאלון שהושלם ללא תחומי טיפול מופיע בתור הנציג. סקירתו אינה מחייבת עריכת תשובות או אימות שדות מחדש.
3. נוספה פעולת שיוך נציג עם בדיקת חשבון פעיל, הרשאת מנהל ובדיקת גרסה. גם הבורר וגם תור הפעולות מסכימים מהו נציג פעיל.
4. אחרי צירוף, השלמה, הגשה ואישור מופיע המשך מפורש; במשימה מקצועית שהוגשה ההמשך קודם לפירוט הממצאים.
5. סיבת החזרת ניתוח מוצגת למקצוען. מצב המתנה ללקוח מסביר כיצד לחזור לטיפול.
6. מסמך משותף מגיע רק לסביבת בעל המקצוע שהורשה; ביטול שיתוף מסיר אותו. אין הוספת גישה לתיק המשפחה.
7. קישור לפריט חסר מציע חזרה מפורשת. הזמנת משתמש שאינה זמינה בדמו מוסברת לפני הצגת טופס שלא יכול להצליח.

## אימות

`check-role-handoffs.mjs` מפעיל רצף UI חדש של ניתוח → החזרה → הגשה → אישור → פגישה חדשה → החלטה → ביצוע → דיווח → אישור, במחשב ובנייד. אינו מזריק מצב ואינו מסתפק בנתוני המשימות המוכנים.

נבדקו גם מסלולי הלקוח, חמשת החשבונות, המשווק, ניהול, השיחה והדוח דרך בדיקות הדפדפן הקיימות, כולל רוחב 320. נוספו בדיקות ליציאות מהמשימות, סקירה ללא טפסים, קליטת שאלון, שיוך והרשאות.

הבדיקה היא של הדמו ומימושיו המקומיים. לא הופעלו חיוב, הזמנת משתמש אמיתית או פרסום API במסגרת משימה זו.
