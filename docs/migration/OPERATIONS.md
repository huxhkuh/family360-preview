# תפעול, גיבוי וחזרה לאחור

המסמך מתאר סביבת בדיקה. אין אישור להעברת תעבורה או מידע מייצור.

## הפרדת סביבות

ממשק: `mesudarim360-staging.pages.dev`. API: Worker בשם `mesudarim360-api-staging`. מסד: `mesudarim360-staging`. קבצים: bucket פרטי `mesudarim360-documents-staging`. אין בהם נתוני משפחות שהועתקו מייצור.

הדומיין הראשי ו־www עדיין שייכים ל־Pages הישן `family360`. ה־DNS של Resend/DMARC לא שונה. פרויקט Auth הקיים משותף כרגע; נדרש פרויקט Auth נפרד אם רוצים לבודד גם משתמשים, מכסות דואר והגדרות MFA. אין לשנות מסלול בשביל זאת בלי אישור.

## הפעלה מקומית

- `npm ci`
- `npm run test:server` — בדיקות הרשאות, זרימת עבודה, אסימונים חתומים וגיבוי.
- `npm test` — גם בדיקות הלוגיקה הקיימות.
- `npm run check:server`
- `npm run dev:live -- --mode staging`
- `npm run dev:api` — ברירת המחדל חוסמת Auth עד להגדרה מפורשת.
- `npx vite build --config vite.live.config.ts --mode staging`

`.env.staging` ו־`server/.dev.vars` אינם נכנסים ל־Git. בפרונט מותר רק מפתח Supabase ציבורי (`anon`/publishable), לעולם לא service-role. הבנייה החיה מחליפה את מתאם הדמו; אין בה בחירת תפקיד או נתוני משפחות מדומים. הרשמה יוצרת תמיד תפקיד client. הסבה למנהל תיעשה רק לאחר בקשת המשתמש לאחר ההתחברות, ותדרוש MFA.

## גיבוי ושחזור

`scripts/migration/secure-backup.mjs` מצפין כל קובץ ו־manifest ב־AES-256-GCM, עם IV חדש לכל קובץ. ה־manifest כולל גודל ו־SHA-256. שמות קבצים אינם נחשפים מחוץ להצפנה. לפני שחזור נבדקים כל הקבצים, תגי האימות והנתיבים. השחזור מסרב לדרוס תיקייה קיימת.

הכלי אינו מושך בעצמו מידע מהענן. תחילה יש להכין יצוא עקבי של המסד וכל גרסאות R2, ורק אחר כך להצפין. משתנה `BACKUP_KEY` נמסר דרך מנהל סודות; אין לשמור אותו במאגר, בשורת הפקודה, בלוג או ביחד עם הגיבוי. יש לשמור עותק מפתח במנהל סודות נפרד שניתן לשחזור.

```text
node scripts/migration/secure-backup.mjs backup SOURCE_DIRECTORY NEW_ENCRYPTED_DIRECTORY
node scripts/migration/secure-backup.mjs verify ENCRYPTED_DIRECTORY
node scripts/migration/secure-backup.mjs restore ENCRYPTED_DIRECTORY NEW_EMPTY_TARGET
```

לפני מידע אמיתי: לגבות PostgreSQL באמצעות pg_dump בפורמט custom, עם schemas ותפקידים/מדיניות הרלוונטיים ליישום; לשמר גם מיפוי Auth, הגדרות Auth, buckets ו־objects. סיסמאות וחומרי MFA נשארים ב־Supabase ולא מועתקים ל־D1. גיבוי Auth צריך להיות בהתאם ליכולות הגיבוי של Supabase, ולא ייצוא ידני לצ׳אט.

ל־D1: יצוא SQL עקבי (`wrangler d1 export ... --remote --output ...`) ושמירת מועד/גרסת פריסה. ל־R2: מפתחות אינם נדרסים; יש להעתיק את כל האובייקטים, לרבות גרסאות קודמות, לרשימת גיבוי עם SHA-256. לצילום עקבי יש לעצור זמנית כתיבות בסביבה המגובה, להשלים בקשות פעילות, לייצא DB ולהעתיק קבצים, לאמת שכל object_key שב־document_versions קיים, ואז לפתוח כתיבות. יש לבדוק שחזור למסד חדש ול־bucket חדש ולבצע הורדה מורשית של קובץ סינתטי. Time Travel לבדו אינו גיבוי לקבצים.

טרם הושלם גיבוי ענן מלא, תזמון גיבוי או תרגול שחזור ענן. אין להעביר מידע קיים לפני השלמתם. בדיקת המלאי החי מצאה 0 משתמשים ו־0 קבצים; עדיין יש לשמר סכמה ושתי רשומות אוטומציה ושני מונים.

## מעבר וחזרה לאחור — רק אחרי אישור

1. להקפיא שינויים וליצור גיבוי מאומת ועותק DNS. לשמור מזהי פריסות קודמות ואת Site URL/rules/origins המקוריים.
2. להשלים מיפוי שדות, פונקציות ונתונים. לבדוק FK, מספרי רשומות, סכומי כספים, שיוכים, קבצים וחתימות.
3. לבדוק הרשמה, אימות דוא״ל, כניסה, שחזור סיסמה, MFA, השבתה, כל תפקיד, ושמירה מקבילה בדומיין הבדיקה.
4. לאחר אישור מפורש בלבד, להעביר את הדומיין לממשק ול־API המאומתים ולעדכן Auth redirects ו־CORS לכתובות המדויקות. לשמר DNS של דואר.
5. אם התקלה מתגלה לפני כתיבות חדשות: להחזיר פריסת UI וניתוב קודמים. לאחר כתיבות חדשות: לעצור כתיבות ולשמר את שתי הסביבות; לא לבצע חזרה עיוורת שתאבד שינויים. להכין ייצוא הפרשים ובדיקת התאמה לפני פתיחה מחדש.
6. אין למחוק את PostgreSQL או הקבצים המקוריים. אין לשנות תוכנית חיוב ללא אישור.

## מגבלות מימוש שיש להשלים לפני ייצור

- חלק מפעולות ה־RPC ממומשות אך עדיין חסרות בדיקות קבלה פרטניות; עצם קיומו של handler אינו הוכחת תאימות מלאה לשרת הישן.
- בדיקות השרת משתמשות ב־SQLite מקומי ובשירות Auth מדומה עם חתימות אמיתיות. הן אינן מחליפות תרגול משתמשים מול Cloudflare/Supabase.
- ניהול גרסאות אטומי משתמש כרגע במונה גלובלי: שינוי מקביל מחזיר CONFLICT. יש למדוד עומס לפני הרחבה.
- עד 500 תיקים בתצוגה הראשונית; חיפוש עם עימוד חושף את שאר התיקים לפי הרשאה. המסך לא נועד לטעון את כל המסד.
- פעולות דואר עסקיות, טלפוניה וסליקה אינן מחוברות לספק. אין לסמן הודעה כנשלחה או תשלום כבוצע.
- נדרש לאמת כללי מעבר HTTPS/כתובת ראשית, Auth redirects, וגיבוי ענן. המחיר בדף השיווקי אינו מימוש סליקה.
