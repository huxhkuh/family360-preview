# מצב עבודה — 26.10.2026

**אינו מוכן לייצור עסקי.** בעקבות בקשת המשתמש לפרוס ב־`family360.pages.dev`, סביבת הבדיקה מוצגת כעת בפרויקט Pages הקיים `family360`, כולל הדומיינים המחוברים אליו. זוהי החלפת הפריסה הציבורית באישור המשתמש; השרת, D1 ו־R2 נשארו משאבי staging. DNS ותוכנית החיוב לא שונו. לא הועבר מידע ולא נמחקו מסד או קבצים קיימים. הוראות חזרה לפריסה הקודמת ב־[FAMILY360-DEPLOYMENT.md](FAMILY360-DEPLOYMENT.md).

נבנו סכמת D1, שרת Workers, מתאם API לממשק העדכני ונתיב הרשמה אמיתי. התפקידים נשמרים בשרת; לקוח אינו יכול לבחור תפקיד. בקשות דורשות חשבון פעיל, אסימון Auth תקין והרשאה לתיק/משימה. מנהל חייב aal2. R2 פרטי וגישת קבצים עוברת דרך בדיקת הרשאה. העלאות מוגבלות ל־20MB ו־PDF/PNG/JPEG/WebP לפי MIME, סיומת וחתימת קובץ. קובץ חדש אינו דורס גרסה קודמת. אירועים רגישים נרשמים בלי תוכן המסמך או השאלון.

## אימות שבוצע

- 339 בדיקות ב־37 קבצי בדיקה עברו, לרבות 31 בדיקות חדשות בשרת/גיבוי.
- TypeScript לממשק ולשרת עבר; build של staging עבר (קיימת אזהרת גודל bundle, כ־966KB לפני gzip).
- בדיקות ES256 חתומות: זיוף חתימה, issuer/audience/role/expiry/iat, חשבון מושבת, Auth חסום, metadata שמנסה להעלות הרשאות, MFA ו־CORS.
- בידוד שני תיקים וחמשת התפקידים; מסמכים עם שיתוף וביטול; זרימה מניתוח דרך פגישה ועד אישור ביצוע; מניעת כתיבה חלקית/מיושנת; יומן עמלות ו־idempotency.
- גיבוי מוצפן: round-trip של SQL וקובץ סינתטי, סירוב דריסה, זיהוי מפתח שגוי ושינוי ciphertext לפני שחזור.
- בענן D1: 43 טבלאות, 0 פרופילים, FK תקין; batch שגוי בוטל ללא שאריות.
- בדפדפן מקומי: דף הבית, מסך כניסה וטופס הרשמה נפתחו; נבדק חזותית טופס ההרשמה. לא הוזנו פרטי משתמש ולא נוצר חשבון בבדיקה.
- פריסת Pages הושלמה לאחר כניסת Wrangler עם keyring. כתובת קבועה: https://mesudarim360-staging.pages.dev; הפריסה המעודכנת `38e95e56-ec03-4dfe-9069-db9969c1bc7d` במצב `success`. גרסת Worker מעודכנת `170d9d2685ad49f3bcde0c3a3650dd7d`; אומתו שוב AUTH_ENABLED=true וחיבור ל־D1 ול־R2 של staging בלבד.
- בדיקת `npm run test:runtime` מפעילה את קוד השרת במנוע workerd מקומי עם D1 ו־R2: כל המיגרציות, FK, rollback אטומי, health, CORS וחסימת גישה אנונימית ל־RPC ולמסמכים עברו. אינה מחליפה בדיקת HTTP בסביבה הפרוסה.
- בכתובות staging הישירות נמצאה חסימת NetFree. לאחר הפריסה המבוקשת ל־`family360.pages.dev`, הממשק ו־API זמינים באותו מקור באמצעות service binding. בבדיקה חיה: דף ו־health החזירו 200, health דיווח staging ואימות פעיל, RPC והורדת מסמך ללא אסימון החזירו 401, preflight מורשה 204, מקור זר 403. תגובות API מוגדרות no-store. מסכי הכניסה ושחזור הסיסמה נפתחו בדפדפן. לא נשלח דוא״ל ולא נוצר משתמש בבדיקות אלה.
- תוקנו התראות תלויות באמצעות Zod 4.6.7, Vite 8.3.5, Vitest/coverage 5.0.5 ו־Wrangler 4.153.0. Miniflare נעול לגרסה התואמת ל־Wrangler (`5.20261023.0-beta`) כדי לבדוק את תאריך התאימות בפועל. npm דיווח על 0 חולשות ידועות אחרי ההתקנה; גם audit נפרד לתלויות הייצור עבר. 339 הבדיקות, בדיקות TypeScript, בניית staging ובדיקת runtime עברו לאחר העדכונים. זו אינה הוכחה שאין פגיעויות.

## עבודה שנותרה

1. הושלם: כניסת Wrangler ופריסת Pages, לרבות חיבור בכתובת המאושרת `family360.pages.dev` לפי בקשת המשתמש. אין צורך בגישת דפדפן ישירה לכתובת workers.dev.
2. הושלם: נוספה ונבדקה הפניה מדויקת ל־https://mesudarim360-staging.pages.dev ב־Supabase. Site URL ושלוש ההפניות המקוריות נשמרו. בדיקות קישורי דוא״ל בפועל עדיין ממתינות.
3. בדיקות כניסה עם חשבון אמיתי, אימות דוא״ל, שחזור סיסמה ו־MFA. HTTP בסיסי וחסימת גישה אנונימית כבר אומתו דרך הכתובת המאושרת; בדיקות זרימת Auth המלאה טרם בוצעו. ההפניה ל־`https://family360.pages.dev` קיימת ברשימת ההפניות המאושרות של Supabase.
4. תרגול מלא לכל הפעולות, גם ברמת UI. רשימת handlers אינה הוכחה לשימור כל פרט עסקי. השלמת בדיקות תאימות, עומס וחריגות.
5. קטלוג שירותים/מסמכים עסקי מאושר, שיוך נציגים ובעלי מקצוע, חשבון מנהל ראשון לאחר בקשת המשתמש. אין חשבונות דמו או הרשאת מנהל אוטומטית.
6. גיבוי ענן מלא מוצפן, שחזור DB וקבצים לסביבה חדשה, תזמון ושמירת מפתח מאובטחת. הכלי המקומי קיים; תהליך ענן מלא עדיין לא בוצע.
7. לפני ייצור: אימות HTTPS/כתובת ראשית והפניות, הגדרות מקור, עלויות ותוכנית מעבר מאושרת. אין לחבר סליקה/דואר עסקי כאילו קיימים בלי ספק ותהליך מתאים.
