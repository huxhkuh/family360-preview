# מנטה ואוויר — טפסים מקצועיים וניהול

השינויים מיושמים בדמו המקומי בלבד, בענף `codex/mint-call-workspace`. לא בוצעו push, פריסה, שינוי Auth, משלוח הזמנות או הפעלת שירות חיצוני. הדמו הציבורי ומערכת הייצור לא שונו.

## המיפוי לפני העבודה

נסקרו מסכי הניתוח, הביצוע, מאגר ההצעות, המשתמשים, השירותים, בעלי המקצוע, הנציגים, סוגי המסמכים, התבניות, האוטומציות, ההגדרות, ההזמנות, הספרייה ויומן הפעילות. נבדקו גם חוזי ה־RPC בקובצי SQL של הפרויקט המקורי, לקריאה בלבד.

הפערים המרכזיים היו אובדן טפסים במעבר, ערבוב שמירת ניתוח והגשתו תחת כפתור אחד, הצגת טופסי עדכון וסיום ביצוע יחד, ורשימה ארוכה של טפסי ניהול פתוחים ללא בחירת רשומה. שגיאת JSON בתוך אזור מתקדם מקופל לא הובילה לשדה שדורש תיקון. כשירות מקצועית נפתחה עם תיבות ריקות גם כאשר כבר היו הרשאות לתחום.

## מה השתנה

### ניתוח מקצועי

- נשמרו כל פרטי ההשוואה: סוג, רמת בדיקה, תקופה, סכומים, תיאורים, בסיס חישוב, תנאים, מקורות, עלויות מעבר ותאריכים. נשמרו גם חומרה, סיכום ללקוח והערה פנימית.
- כפתורים נפרדים לשמירת טיוטה ולהגשה לאישור. אפשר לשמור טיוטה חלקית; ההגשה דורשת את שדות החובה הקיימים.
- רשימת החוסרים להגשה מוצגת בראש העבודה. חוסרים מקצועיים נוספים בהשוואה ממשיכים להיות מוצגים, בלי להמציא שער אישור חדש.
- תצוגה מקדימה ללקוח מתוך הטיוטה, ללא ההערה הפנימית, וחזרה לעריכה בלי אובדן נתונים.
- שגיאות ליד השדות ומיקוד בשדה הראשון; גם שדות ההשוואה משתמשים כעת ברכיב השדה הנגיש.
- הטיוטה נשמרת בזיכרון במעבר וניתן לחזור אליה מרשימת הטיוטות. שדות המטען שאינם נערכים כאן, כגון findings/actions/attachments/result_values, נשארו במטען השמירה.

### ביצוע מקצועי

- אזור הנחיות ומצב ברור; לשוניות לעדכון התקדמות ולדיווח סיום.
- נשמרו כל פעולות העדכון: תיעוד, הודעה בתיק, המתנה ללקוח, בקשת השלמה וחזרה לטיפול. מוצגת השפעת הבחירה לפני הפעולה, והכפתור מבדיל בין שמירה לשליחת הודעה בתיק.
- טיוטות נפרדות לעדכון, לדיווח סיום ולהחזרה לטיפול. דיווח סיום לא עוקף טיוטת עדכון פתוחה.
- סיום מקצועי נשאר דיווח לבדיקת הנציג; רק בעל הרשאת אישור יכול לאשר או להחזיר לטיפול. נשמרו היסטוריית הטיפול, הוראות הביצוע ופרטי הקשר המותרים.
- סכום אפס שנמדד נשמר כ־0, בעוד שדה ריק נשלח כ־null.
- הודעת הצלחה או שגיאה של טופס אחד אינה עוברת לטופס אחר.
- נוספו חיפוש וסינון מצב לרשימת המשימות, עם שימור הבחירות במעבר.

### ניהול

- כל הלשוניות והפעולות המקוריות נשמרו. רשימות המשתמשים, השירותים, בעלי המקצוע, הנציגים, סוגי המסמכים, התבניות והאוטומציות מוצגות כרשימה לצד אזור עריכה. בנייד הרשימה מעל הטופס.
- חיפוש, הרשומה שנבחרה, הלשונית וכל שדות הטופס נשמרים במעבר. תיבות סימון והרשאות מרובות נשמרות כקבוצה, כולל הסרת סימון.
- לפני שמירה מוצגת תצוגת „לפני / אחרי” של השדות ששונו. ביטול טיוטה נעשה באישור בתוך המסך.
- כל ארבעת שדות ה־JSON המתקדמים נשארו זמינים. קלט שאינו מערך JSON תקין מציג שגיאה ליד השדה ופותח את האזור המקופל. מבנה המידע העסקי עדיין כפוף לאימות השרת.
- מוצגות כשירויות מקצועיות קיימות; בחירת שירות ממלאת את תיבות הניתוח והביצוע לפי הנתונים הקיימים.
- טפסי יצירה מתאפסים רק לאחר הצלחה, ומאפשרים יצירת כמה רשומות נפרדות ברצף. שגיאה משאירה את התוכן לתיקון.
- טיוטות הזמנה ופריטים בספרייה נשמרות במעבר. יצירת הזמנה אמיתית אינה ממומשת בדמו ומחזירה הודעה מפורשת, ללא אובדן הטופס.
- שם המערכת שנשמר מוצג בכותרת הממשק.

### מנגנון משותף

`RetainedForm` שומר בזיכרון את השדות המקוריים של טפסי HTML. לא נוסף אחסון מקומי של פרטי משתמש. גם אם שמירה מוקדמת מסתיימת לאחר שהמשתמש חזר והוסיף עריכה, הטיוטה החדשה אינה נמחקת. קיימת בדיקה ייעודית ללוגיקת ההשוואה הזו.

הסימולציה המקומית הורחבה לניהול רשומות ולמסלול ביצוע מלא, עם נתוני דוגמה לתבנית, אוטומציה ומשימת ביצוע. פעולות ההדגמה אינן יוצרות חשבונות, שולחות הודעות חיצוניות או מפעילות תזמון. חוזי הקריאה של הממשק נשמרו; קוד השרת המקורי לא נערך.

## בדיקות

תוצאה סופית: 106 בדיקות יחידה ב־15 קבצים עברו; TypeScript ובניית Vite עברו. בדיקות הניתוח, הביצוע והניהול עברו בכל שלושת הגדלים, כולל בדיקת ההפרדה של הודעות הצלחה בין הטפסים. בדיקות הרגרסיה של המשפחות והשיחות עברו. `git diff --check` עבר.

פקודות האימות:

```powershell
npm test
npm run build
$env:DEMO_URL='http://127.0.0.1:5250/family360-preview/'
npm run test:professional-admin
npm run test:demo
node scripts/check-journey.mjs
npm run test:ux
```

- בדיקות יחידה כוללות הרשאות בסימולציה, אימות נתוני ניהול ללא שינוי חלקי, מניעת מזהה כפול, הגנה על הרשאות המנהל של עצמו, בעלות ומצבי משימה, דיווח ואישור ביצוע, שימור אפס ומניעת מחיקת עריכה חדשה בעקבות שמירה קודמת.
- `check-pro-admin.mjs` בודק Chromium במחשב 1440×1000, טאבלט 820×900 ונייד 390×844. נבדקים ניתוח חלקי והגשה, שדות חובה ומיקוד, מעבר לתצוגה מקדימה וחזרה, שחזור טיוטות, הודעה והיסטוריה, דיווח/החזרה/אישור, כל סוגי טפסי הניהול, JSON שגוי באזור מקופל, יצירות חוזרות, שגיאת מזהה כפול, כשירות קיימת, טיוטת ספרייה והסתרת ניהול ומשימות מקצועיות מהלקוח.
- בדיקות הרגרסיה הקיימות מכסות ארבעה תפקידים, משפחות, שאלון, שיחה, מעקב, רשימת בדיקה, חיפוש, גלילה וטעויות שמירה.
- בדיקות הדפדפן בודקות שאין שגיאות JavaScript, בקשות חיצוניות או גלילה אופקית במסכים המרכזיים שנבדקו.
- צילומי מסך של טפסים מקצועיים וניהול נבדקו חזותית. תמונות ותוצאות נוצרות ב־`test-results/pro-admin-after` (לא נכלל ב־Git).
- הבדיקה החדשה נוספה לתהליך האימות לפני פרסום עתידי. התהליך החיצוני לא הופעל.

## גבולות האימות

- האימות מול נתונים סינתטיים ומתאם מקומי. אין כאן אישור ל־RLS, Auth/MFA, העלאות, משלוח הודעות, הזמנות אמיתיות, עבודות רקע או הרשאות בשרת חי.
- שינוי תפקיד בכלי הדמו הוא סימולציה ואינו אימות Auth. שינוי רשומת משתמש בהדגמה אינו יוצר או מבטל חשבון אמיתי.
- טיוטות נשמרות במעבר מסכים במהלך העבודה, אך נמחקות ברענון, יציאה או החלפת תפקיד. אין שמירה בין מכשירים.
- חוזי שמירת הניתוח והניהול המקוריים אינם כוללים גרסת עדכון אופטימית. לא נוספה הבטחה למיזוג שינויים בין שני משתמשים. יש לאמת ולתכנן זאת מול שרת פיתוח לפני העברה לייצור.
- נבדק Chromium בתצוגות מדומות; לא Safari/Firefox, מכשירים פיזיים או קורא מסך מלא.
- נשארה אזהרת Vite על גודל החבילה הראשית, כ־591KB לפני דחיסה. לא הוחלף מנהל החבילות ולא נוספו תלויות.

מסלול התנסות: בעל מקצוע → משימות → A-004 לניתוח, או משימות ביצוע → E-001. למנהל: ניהול → שירותים / נציגים / בעלי מקצוע, עריכת שדה, מעבר לרשומה אחרת וחזרה דרך „טיוטות בעבודה”.
